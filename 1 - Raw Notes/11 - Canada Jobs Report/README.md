# 多倫多工程職缺追蹤

## 使用方式

- [JOBS.md](JOBS.md)：累積職位總表。JC 修改「我的選擇」與「我的備註」；自動更新必須保留這兩欄。
- `weekly/YYYY-MM-DD.md`：每次找到的職位、核查來源和技能差距，保留歷史快照。
- `monthly/YYYY-MM.md`：合併該日曆月的所有週報，去重並整理 JC 的選擇。

「我的選擇」可填：待選、保留、略過、已申請。新職位預設待選；不替 JC 做保留或申請決定。略過的職位保留歷史但不再次推薦，除非 JC 更改選擇。已關閉的職位標記關閉，不刪除。

## 篩選要求

- 僅 Toronto / GTA 的 Backend、Full Stack、Platform 工程職位；遠端職位須允許住在 Toronto 並從加拿大受聘。
- 優先 Staff / Senior Staff / Principal；Senior 或技術 Lead 須符合薪資與工作內容。
- 目標基本年薪 CAD 300,000 左右，分開記錄 base、bonus 和股票；不把 total compensation 當 base。不列明顯低於目標的推薦。
- 公司須成熟、有可核查的規模與營運歷史；排除小公司與創業初期公司。「成熟」不代表保證穩定。
- JC 是目前住在美國、願意搬到 Toronto 的美國公民。逐項查明公司是否接受境外候選人、是否提供工作許可所需協助。未確認就寫待確認，不能因國籍或 offer 推定工作許可必定獲批。
- 公司官網／官方 ATS 職缺頁為主要來源；核查職缺仍開放、勤務地、CAD 基本薪資、所需技能和搬遷／工作許可條件。
- 不湊數；沒有符合條件職位就如實記錄。薪資未公開但極高匹配、可能達標者僅列「待確認候選」，不能混入已確認達標的推薦。

## 更新規則

週報沿用每週一早上（America/Chicago，約 9 點）的現有排程；首個排程為 2026-10-12。月報預設每月 1 日早上（America/Chicago，約 9 點），彙整上一個日曆月所有週報，包括有五週的月份；首份為 2026-10 月報，於 2026-11-01 產生。

更新前讀取本文件、JOBS.md 及相關既有報告。以公司＋職缺 requisition ID 為固定 ID；無官方 ID 時用公司＋正規化官方網址識別。不同週重複發現只更新 last seen，保留 first seen 和使用者欄位。若使用者刪除總表的一列，從歷史重新加入前須標記待釐清，不可擅自視為新的待選職位。

每次寫入先取得最新 SHA，發生衝突重新讀取並合併；僅修改本資料夾，不覆寫無關檔案。保存完成後通知 JC 並附 GitHub 連結；保存失敗如實回報。

## 報告內容

週報 summary 表至少包含：固定 ID、公司、職位、地點／模式、CAD 基本年薪及來源、匹配程度及具體依據、技能差距、境外聘用／工作許可確認程度、申請優先級、直接職缺連結、核查日期。細節可放表格下方，避免表格過寬。

月報：列出來源週報及覆蓋日期；按固定 ID 去重；區分 JC 保留／略過／已申請／待選；重新核查保留職位是否仍在招，標記薪資或聘用條件變更；總結重複出現的技能差距與準備順序。只有四份週報時合併四份，有五份時全部納入，資料不足要說明，不能虛構缺失週報。
