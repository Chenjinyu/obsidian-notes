# Content

## **Overview:**
```
Technical Phone Screen   →  filter/gate stage, quick check
Coding Interview         →  deep evaluation, multiple rounds
```

---

## **Side by side comparison:**

| | Technical Phone Screen | Coding Interview |
|--|----------------------|-----------------|
| **Purpose** | filter out weak candidates | deeply evaluate strong candidates |
| **Duration** | 30-60 min, 1 round | 45-60 min per round, 2-4 rounds |
| **Difficulty** | Easy/Medium | Medium/Hard |
| **Problems** | 1-2 problems | 1-2 problems per round |
| **Interviewer** | 1 engineer | 1 engineer per round, different each round |
| **Format** | phone/video + shared editor | virtual onsite or onsite in person |
| **Depth** | get it working | correct + optimized + edge cases + design |
| **System Design** | rarely asked | often included at senior level |
| **Behavioral** | light background questions | full STAR format behavioral round |
| **Stakes** | low — just moves you forward | high — determines offer |

### Virtual Onsite vs Onsite in person
#### Traditional Onsite (before COVID):
```text
- fly to company's city (they pay for travel)
- spend full day at their office
- meet interviewers in person
- whiteboard coding on physical whiteboard
- lunch with team
- 5-6 rounds back to back
```

#### Virtual Onsite (now common):
```txt
- stay at home
- spend full day on video calls (Zoom, Google Meet)
- code on shared online editor (CoderPad, HackerRank)
- 5-6 rounds back to back, same as in person
- no travel needed
```

#### They are identical in terms of:
```text
✅ same number of rounds
✅ same difficulty
✅ same evaluation criteria
✅ same stakes — this is the final interview before offer
```

## **Depth difference on same problem:**

```
Phone Screen — Two Sum:
  ✅ working solution
  ✅ basic complexity analysis
  → done, move on

Coding Interview — Two Sum:
  ✅ clarify all edge cases first
  ✅ brute force approach first, then optimize
  ✅ optimal hashmap solution
  ✅ explain why hashmap over sorting
  ✅ time AND space complexity
  ✅ test with multiple inputs including edge cases
  ✅ discuss follow-ups:
       "what if array is sorted?"
       "what if we need all pairs, not just one?"
       "what if numbers can overflow?"
  → much more thorough
```

---

## **Overall interview pipeline:**

```
Resume Screen         (no interview, HR reviews)
      ↓
HR/Recruiter Call     (background, salary, availability)
      ↓
Technical Phone Screen  ← quick filter, 1 round
      ↓
Coding Interview        ← deep eval, 2-4 rounds
      ↓
System Design           (mid/senior level)
      ↓
Behavioral Round
      ↓
Hiring Manager Round
      ↓
Offer
```

---

**In short:**
- Phone screen = *"can this person code at all?"*
- Coding interview = *"how well can this person code, think, and communicate?"*

The phone screen gets your foot in the door. The coding interview determines whether you get the offer.
