# Content
**Dynamic Programming** (DP) is a programming paradigm that can systematically and efficiently explore all possible solutions to a problem. As such, it is capable of solving a wide variety of problems that often have the following characteristics:

1. The problem can be broken down into "overlapping subproblems" - smaller versions of the original problem that are re-used multiple times.问题可以分解为“重叠子问题”——这些子问题是原问题的较小版本，并且会被多次重复使用。
2. The problem has an "optimal substructure" - an optimal solution can be formed from optimal solutions to the overlapping subproblems of the original problem. 问题具有“最优子结构”——原问题的最优解可以由其重叠子问题的最优解构成。(**Important**)

for example, the brute force solution for calculating the Fibonacci sequence has **exponential** time complexity, while the dynamic programming solution will have **linear** time complexity because it **reuses the results of subproblems** rather than recalculating the results for previously seen subproblems.

time complexity is O(n)

2. Why DP is Faster 

In a [naive recursive tree](https://www.geeksforgeeks.org/dsa/program-for-nth-fibonacci-number/), the number of function calls grows exponentially because `fib(n-2)` is recomputed every time it is needed by `fib(n)` and `fib(n-1)`. 

- **Memoization (Top-Down):** When a value like `fib(5)` is first calculated, it is saved in a [lookup table](https://matthewaquino.medium.com/intro-to-dynamic-programming-with-the-fibonacci-sequence-d9005e577854). Future calls for `fib(5)` return the result in O(1) time.
- **Tabulation (Bottom-Up):** This [iterative approach](https://algodaily.com/lessons/fibonacci-sequence-using-dynamic-programming-379b70c0) starts from `fib(0)` and `fib(1)`, filling an array until it reaches `n`. Each value is computed exactly once in a single loop.
3. Advanced Considerations 
* Space Optimization: Since calculating fib(n) only requires fib(n-1) and fib(n-2), you can discard older values. This keeps space complexity at \(O(1)\).
* Bit Complexity: Technically, if \(n\) is very large, adding two numbers takes \(O(n)\) time because the number of bits grows linearly with \(n\). In this strict model, the complexity of the DP approach is actually \(O(n^{2})\).
* Faster Alternatives: For extremely large \(n\), methods like Matrix Exponentiation or Binet's Formula can achieve \(O(\log n)\) time.
