# Problem
Given an array of integers `nums` and an integer `k`, return _the total number of subarrays whose sum equals to_ `k`.
A subarray is a contiguous **non-empty** sequence of elements within an array.

**Example 1:**
**Input:** nums = [1,1,1], k = 2
**Output:** 2

**Example 2:**
**Input:** nums = [1,2,3], k = 3
**Output:** 2

**Constraints:**
- `1 <= nums.length <= 2 * 10^4`
- `-1000 <= nums[i] <= 1000`
- `-10^7 <= k <= 10^7`

# Step 2 - Try Brute Force First to help you understand the structure of the problems
```python
from typing import List

def subarray_sum(nums: List[int], k: int) -> int:
"""
worse case: O(n^2). space compliexity: O(n)
"""
	left = ans = window_sum = 0
	prefix = [0] * (len(nums) + 1)
	for i in range(len(nums)):
		prefix[i+1] = prefix[i] + nums[i]
	
	for j in range(len(nums)):
		# calcuate the current window sum form the prefix array
		window_sum = prefix[j + 1] - nums[left]
		# shrink the window as long as the sum is TOO LARGE
		while window_sum > k and left <= j:
			window_sum -= nums[left]
			left += 1
		# After finish the shrinking, if it exactally equals K, we found the match.
		if window_sum == k:
			ans +=1
	
	return ans
```
1. the solution only works with positive numbers, because it uses a sliding window approach to find subarray, and the sliding window can be shrink by left with checking window_sum > k.
### Step2 - Takeaways
#### Sliding window with "Monotonicity" Requirement
	A variable-side sliding window relies on a concept called "Monotonicity"(meaning it only moves in one direction).
	it assumes two golden rules:
		1. **Expanding** the window (moving right) will always increease (or keep the same) the sum.
		2. **Shrinking** the window (moving left) will always decrease (or keep the same) the sum.
	because of these rules, the algorithm always knows exactally what to do: if the sum is too small, expanding the window, if its too big, shrink the window
SO, NEGATIVE NUMBER Breaks the golden rules.

#### for sliding window, always let the left catch up to close the right. 
#### add a placeholder at the begining of the prefix array to represent the state before the first element. for sum and XORs, the placeholder is 0. For product, the placeholder is 1.  this allows us to calculate subarrays starting at index 0 cleanly without writing messy if left == 0: edge-case logic everywhere

from collections import defaultdict
def subarray_sum_hash_map(nums: List[int], k: int) -> int:
	prefix = defaultdict(int) # or {0:1}
	prefix[0] = 1 # this is the placeholder for e.g. subarrary [-2, 2, 3], and k = 3.
	curr_sum, ans =0, 0
	for i in range(len(nums)):
		curr_sum += nums[i]
		if curr_sum - k in prefix:
			ans += prefix[curr_sum - k]
		prefix[curr_sum - k] = prefix.get()
