# Problem
Find all valid combinations of `k` numbers that sum up to `n` such that the following conditions are true:

- Only numbers `1` through `9` are used.
- Each number is used **at most once**.

Return _a list of all possible valid combinations_. The list must not contain the same combination twice, and the combinations may be returned in any order.

**Example 1:**
**Input:** k = 3, n = 7
**Output:** `[[1,2,4]]`
**Explanation:**
1 + 2 + 4 = 7
There are no other valid combinations.

**Example 2:**
**Input:** k = 3, n = 9
**Output:** `[[1,2,6],[1,3,5],[2,3,4]]`
**Explanation:**
1 + 2 + 6 = 9
1 + 3 + 5 = 9
2 + 3 + 4 = 9
There are no other valid combinations.

**Example 3:**
**Input:** k = 4, n = 1
**Output:** []
**Explanation:** There are no valid combinations.
Using 4 different numbers in the range [1,9], the smallest sum we can get is 1+2+3+4 = 10 and since 10 > 1, there are no valid combination.

**Constraints:**
- `2 <= k <= 9`
- `1 <= n <= 60`

```python
class Solution:
	"""
	1. Wrong outer loop:  you will get answer in the below correct solution
	    for digit in range(1, 10):
		    backtrack(digit, n, [])
		
	"""
    def combinationSum3(self, k: int, n: int) -> List[List[int]]:
        ans = []

        def backtrack(start, remain, path):
            if remain == 0 and len(path) = k: 
                ans.append(path.copy())
                return

            if remain < 0 or len(path) > k: return
            
            target_range = n - start
            for idx in range(start + 1, target_range + 1): 
                remain = remain - idx
                
                path.append(idx)
                backtrack(idx + 1, remain, path)
                path.pop()

        for digit in range(1, 10):
            backtrack(digit, n, [])
        return ans
```

# Step 3 - Think about Optimization
```python
class Solution:
	"""
	answer for 1st conclusion of above solution
	for num in range(start, 10): here is exploring vertically. 
	from 1st num, and recusive the 2nd num, 3rd num, etc.
	when num = 1, the backtrack(num + 1, remain - num , path) will move the num to 2 until 9. then return back to num = 1.
	then, num for loop to 2, and then from 2 to 9, then return back to num = 2.
	...
	so, the current num in recusive calls, will traverse to 9. 
	it explores depth-first vertically. (DFS)
	same pattern you can compare: [[M - 0078. Subsets]]
	---- vertically ---->
	[]                  
	├── 1               
	│   ├── 2           
	│   │   ├── 3       
	│   │   ├── 4       
	│   │   ├── 5.      
	│   ├── 3           
	│   ├── 4           
	├── 2
	├── 3
	"""
    def combinationSum3(self, k: int, n: int) -> List[List[int]]:
        ans = []

        def backtrack(start, remain, path):
            if remain == 0 and len(path) == k: 
                ans.append(path.copy())
                return

            if remain < 0 or len(path) > k: return
            
            for num in range(start, 10): 
                # the remain cannot cacluate here. Its a major bug
                # this will permanently modify remian inside loop iterations
                # the remain will be used in other candidate.
                # eg. [1,2,3], after 3 pop, 4 will push into curr. but the remain has been changed globally.

                # remain = remain - num 
                
                path.append(num)
                backtrack(num + 1, remain - num , path)
                path.pop()

        backtrack(1, n, [])
        return ans
```
